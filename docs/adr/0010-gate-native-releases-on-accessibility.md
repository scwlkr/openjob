# Gate native releases on accessibility

Accessibility is a release criterion from the first native slice rather than a remediation phase before public launch. Every feature's automated and virtual-runtime Feature Proof covers its affected accessibility behavior, including semantics, labels, focus order, text scaling, contrast, touch targets, Reduced Motion, and alternatives to color, sound, or gestures. When a change depends on hardware, an operating-system service, or physical assistive-technology behavior, its physical check is deferred to #41 Release Proof and does not block the feature issue from closing after simulator and emulator Feature Proof passes.

The full physical accessibility matrix runs once as Release Proof for each immutable Release Candidate. The exact iOS and Android Candidate Artifacts must pass VoiceOver and TalkBack, system text scaling, Reduced Motion, keyboard or pointer behavior where applicable, and complete touch-only operation. An accessibility change with material platform or release risk must name its deferred candidate-level checks immediately, but physical execution waits for #41 and routine feature work does not repeat the matrix.
