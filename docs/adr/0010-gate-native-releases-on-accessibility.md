# Gate native releases on accessibility

Accessibility is a release criterion from the first native slice rather than a remediation phase before public launch. Every feature's automated and virtual-runtime Feature Proof covers its affected accessibility behavior, including semantics, labels, focus order, text scaling, contrast, touch targets, Reduced Motion, and alternatives to color, sound, or gestures. Physical-device proof is required before a feature issue closes only when the change depends on hardware, an operating-system service, or physical assistive-technology behavior.

The full physical accessibility matrix runs once as Release Proof for each immutable Release Candidate. The exact iOS and Android Candidate Artifacts must pass VoiceOver and TalkBack, system text scaling, Reduced Motion, keyboard or pointer behavior where applicable, and complete touch-only operation. An accessibility change with material platform or release risk may require this candidate-level proof immediately; routine feature work does not repeat the whole matrix.
